# PROJ-1003: Coordinated Multi-Repo Schema Update for Event Routing Key

**Issue Type:** Feature  
**Primary Repository:** `./examples/sandbox-repo`  
**Connected Repositories:** `./examples/sandbox-client`  

## Summary
To support distributed microservice topic partitioning, the event envelope schema must accept an optional `routingKey` field, and the client publisher must be updated to transmit it when configured.

## Acceptance Criteria
1. **Primary Repo (`sandbox-repo`):** `validateEventEnvelope` accepts an optional `routingKey` string. If present and non-empty, the envelope is valid; if present as an empty string or non-string, validation returns an error.
2. **Connected Repo (`sandbox-client`):** `EventPublisherClient` accepts `routingKey` in its constructor configuration and attaches `routingKey` to envelopes generated by `buildEnvelope()`.
3. Unit tests in both `sandbox-repo` and `sandbox-client` pass cleanly.
4. Coordinated pull requests are prepared for both repositories.

## Out of Scope
* Modifying database schema or table migrations.
